# tools/ui-e2e — 界面点测

真的开一个无头浏览器，把界面上的每一项功能点一遍，最后打印 PASS/FAIL。
红了就退出码 1。

## 为什么要有它

`npm run smoke` 只打 HTTP 接口，`npm run shots` 只出图给人看。两者都盖不住一类问题：
**接口是对的，界面没接上**。这类问题在单元测试里全绿，只有真的点一遍才露出来——
本工具第一次跑就抓到两个：

1. 面试官面板的顺序会跟着点击历史走（先取消 HR 再勾回来，面板变成 `[tech, hiring_manager, hr]`），
   而提问编号、契约条数、送进模型的提示词都按面板顺序生成，于是回放模式整盘卡带对不上；
2. 连点两次删除按钮，第二次打到已经删掉的会话上，控制台留下一条 404。

## 用法

```bash
npm run e2e:ui            # 等价于 node tools/ui-e2e/e2e.mjs
node tools/ui-e2e/e2e.mjs --out .tmp/my-run
node tools/ui-e2e/e2e.mjs --help
```

需要系统里有一个 Chromium 内核浏览器（默认找 Windows 的 Edge，路径写死在脚本顶部）
以及一个空闲端口（默认 8811）。跑一次约 1–2 分钟，所以**没有**放进 `npm run verify`。

## 它点的是什么

自起服务（回放模式，不需要 API Key、不联网）后，按顺序覆盖：

| # | 场景 | 断言 |
| --- | --- | --- |
| 1 | 空状态 | 四条机制可见；简历为空时「开始质询」是灰的 |
| 1b | 新手教程 | 第一次打开自动弹出，含三种模式对照与隐私口径；点「知道了」收起 |
| 1c | 配色 | 深色 → 浅色 → 深色，且把选择写进本地存储 |
| 1d | 从文件导入简历 | 给隐藏的 `input[type=file]` 塞一份文本夹具，解析结果直接填进输入框（字数对得上），并写明「已从 resume-import.txt 解析出 36 字（文本）」 |
| 2 | 手打简历 | 真的在 textarea 里输入 87 字，按钮随即亮起 |
| 3 | 回放模式缺卡带 | 界面出现「回放模式找不到这一条记录」并带 `CROSSEXAM_MODE=record` 补救提示；过程面板转「中断」；主张卡片 0 张 |
| 4 | 一键示例 | 简历变成 361 字 |
| 5 | 面试官面板 | 加减面试官时，意图契约条数跟着变（3→4→3→2→3） |
| 6 | 跑完一场 | 5 张主张卡片、5 条判定、4 条建议，界面画出的判定条数 = 服务端，每条判定都写了判定口径 |
| 7 | 下载报告 | 链接存在且真能下到 4836 字符 Markdown |
| 8 | 遥测与契约 | 头部显示调用/回放/追问；契约徽章「与运行时一致」；能展开这位面试官实际拿到的 System Prompt |
| 9 | 清空 | 简历与棋盘都收回空状态 |
| 10 | 历史会话 | 列出两场（已完成 / 失败）；点历史能载回来；点 × 能删掉一场；能把历史清空 |
| 11 | 控制台 | 整轮下来 0 条报错、0 条警告（含所有 HTTP >= 400 的响应） |

## 产物

- `.tmp/ui-e2e/*.png`：关键画面截图（空状态、跑完、判定、历史）
- `.tmp/ui-e2e/summary.json`：每项检查的名字、结果与证据

`.tmp/` 已被 gitignore，产物不会进仓库。

## 两个坑

- 第一次打开会自动弹新手教程。这份脚本每次都用**新建的浏览器 profile**（`PROFILE` 带 `Date.now()`），
  所以教程必然弹出——顺手把它当成一项断言；若换成固定 profile，这一项会因为「看过了」而失败。
- 界面上的按钮文本会带勾（`✓ 压力面试官`），点选时要用**包含**匹配而不是全等；
  历史条目的状态是中文「已完成」/「失败」，不是 `done`。
- **收尾只杀进程是不够的**：Windows 上 Edge 的启动器进程会先退出，`proc.kill()` 与 `taskkill /pid <起点进程>` 都够不到真正的浏览器进程树，
  残留的浏览器继续占着 `--remote-debugging-port`。**只有 CDP 的 `Browser.close` 真能关掉它**，`taskkill /T` 只当兜底。
- **因此开跑前必须预检调试端口**：端口被上一轮的孤儿占着时，脚本会连上旧浏览器——它的 profile 里已经写着「教程看过了」，
  于是「首次打开自动弹教程」必然失败，而根因根本不在被测代码里。现在起浏览器前先 `GET /json/version`，被占用就直接退出并提示怎么清；
  page target 也只认 `url === 'about:blank'` 的那一个（自己刚开的那个空窗口）。教训见 findings F40。
- 中途抛异常时也要收尸：`cleanup()` 在 `finally` 与 `process.on('exit')` 里都会跑，否则下一次跑就撞端口。
