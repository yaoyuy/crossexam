## 二、建远端仓库（⛔ 需要本人操作）

**为什么是 ⛔**：仓库地址与账号归属只有参赛者能决定，AI 拿不到也不该代填。

1. 在 GitHub 或 Gitee 新建**公开**仓库（不要初始化 README，本地已有）。
2. 在仓库根执行（把地址换成真实地址）：

```
git remote add origin <仓库地址>
git push -u origin main
```

3. **推送后立刻核对三件事**：
   - 贡献者列表里只有本人，没有 AI 服务商账号（本仓库提交信息从不写 AI 署名尾注，见 AGENTS.md 第 2.3 节）。
   - `.env` 没有被推上去（`git ls-files | grep -c '^\.env$'` 应为 0）。
   - 仓库首页能直接渲染 README（含截图）。

4. 把真实仓库地址填回 `README.md` 顶部的 `<仓库地址>` 占位，再提交一次（`docs: 填入公开仓库地址`）。

## 四、提交前的最后一遍门禁（可自动跑）

```
npm run verify        # 五道：类型检查 + 73 个测试文件 / 765 条断言 + 9 项真进程冒烟 + 构建 + 14 项性能预算
npm run repro         # 干净目录复现预演，确认评委会看到同一件事（最近一次 86.6 s）
npm run docs:pdf      # 重建技术文档，确认仍是 30 页、没超上限（已到上限，动正文前先想清楚）
npm run export:prompt # 刷新 Prompt 链快照，把最后一次迭代也带进去
git status --porcelain  # 必须为空
```

## 五、这份清单本身也是证据

上面每一条都不是「我觉得没问题」，而是**一条能在评委机器上重跑的命令**：
复现耗时来自 `npm run repro` 的计时，页数来自 `npm run docs:pdf` 读 PDF 的 /Count，
断言数来自 `vitest` 的汇总行，Prompt 链来自会话日志的逐帧解压。

这正是这个项目对「过程可复现性与演进链路」那 25% 的回答：**把交付物做成命令的输出，而不是命令之外的手工制品。**
