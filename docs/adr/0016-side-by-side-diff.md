# ADR-0016：改前改后对照要有上下文，而且只算一遍

- 状态：已采纳（2026-10-27，P11 的 B2）
- 相关：决策 D50 / D51、发现 F62 / F63、`packages/shared/src/revise.ts`、`packages/server/src/report.ts`、`packages/server/src/report-html.ts`、`packages/web/src/components/RevisionBar.tsx`

## 背景

采纳改写之后，简历被真的改过，用户需要一个能核对的东西：哪一句被改成了什么。
报告（Markdown / 可打印 HTML / Word）与界面（采纳栏）都要能回答这个问题，而且必须给出**同一个答案**。

## 决策

1. **聚合只写一遍**。`sideBySide(resumeText, applied)` 产出若干行，报告与界面都读它；两侧都不许自己遍历 `applied` 拼结论。
2. **摆上下文行**。改动之间没动过的原文也要进来，两侧相同，朝改动的方向截断（改动之前留尾巴、之后留开头）。
3. **不做字符级 diff**。中文改写多为整句重写，字符级对齐会碎成无意义的片段。
4. **只在真的采纳过之后出现**。没采纳就不叫「改前改后」；`applied` 为空时两份报告都跳过这一节，章节编号随之回退（复现方式仍然是六）。
5. **界面默认收起**。它是核对时才看的东西，不该长期占着采纳栏的地方。

## 取舍

- 两列不逐字符对齐，换来的是「读得懂」；要逐字对齐应该去看简历本体（右栏已经把改动段标绿）。
- 上下文长度固定 24 字（`SIDE_CONTEXT_CHARS`），超出即截断并加省略号；因此可能出现「上下文」行两侧一模一样的情况——这是刻意的：它标的是位置，不是内容。
- 报告里多一节意味着章节编号会随内容变（六七之间来回）。选「编号连续」而不是「编号固定、留个空号」，因为报告是给人读的。
