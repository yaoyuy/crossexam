# ADR-0020：整场打包成一个文件，把「不许有外链」写成断言

- 状态：已采纳（2026-10-27，P11 的 C3）
- 相关：决策 D56、发现 F71/F72、`packages/server/src/bundle.ts`、`packages/server/src/http/app.ts`

## 背景

能导出的东西一直是四份：报告 md / html / doc，简历 txt / html / doc。自己带走够用，
但**发给别人不够用**——对方要收四个文件，还得自己判断哪个是哪个；发到微信里基本会散掉。
而这个产品最需要被传播的那一句话（「你简历里这句话，撑不住」）恰恰是在报告里的。

于是要一份「打包版」：一个文件，双击就看完整场。

## 决策

1. **报告正文不重写一份，直接嵌 `renderReportHtml` 的输出**。切掉它的 `<div class="footer">` 之前的部分，
   整段塞进打包文件，再在后面接两节附录。理由与 F63 同族：同一份事实两套渲染，
   迟早会长成两个版本——报告里说「变好 4 条」，打包里说「变好 3 条」，用户没法判断哪个是真的。
2. **「不许出现 http(s)://」是一条可执行的断言，不是文档里的一句话**。
   收件人的机器可能断网，一旦混进外链字体、统计脚本或图片，他看到的就是半张白纸，
   而这种失败在**发件人这边完全看不见**——他没有理由去点开自己刚发出去的东西。
   所以 `packages/server/test/bundle.test.ts` 里直接断言 `html.includes('http://') === false`，
   另外守一条 `<img|iframe ... src=>` 也不许出现。这条断言红了，等于「这个文件发出去会缺东西」。
3. **时间线只摆有意义的时刻**：`TIMELINE_KINDS` 收 stage / claims / requirements / probes /
   verdicts / suggestions / counter / error 八类；answers 与 budget 不单列（它们的后果已经体现在
   追问和判定里，逐条倒出来是没人读的日志）。每个阶段把 stage 键名翻成人话（抽取主张、读岗位要求……），
   键名是给开发者看的，读者不该见到 `jd-merge` 这种东西。
4. **简历那一节在读库之外自己重算**：`applyRevisions(view.session.resumeText, applied)` + `movedSpans`，
   与 `revisions.ts` 的 `toView` 走同一条路。不读 `revised_resume` 表——打包函数要能被独立调用，
   输入只有 `SessionView` 与 `applied`，它不该依赖「库里正好存着那一版」。
5. **附件而不是内联**（`content-disposition: attachment`），文件名 `crossexam-bundle-<id>-<时间>.html`。
   内联的话浏览器会把它当页面渲染，右键另存反而更容易存成带后缀的乱码；而这是一个要往外发的文件。
6. **入口条件与报告三颗按钮一致**：没有主张就没有可打包的东西。按钮排在最后——前三颗是「自己带走」，
   这一颗是「发出去给人看」，动作的性质不同。

## 取舍

- **不做图片 base64**：这一份里根本没有图片（判定是文字加配色，配色在 CSS 里）。
  为「以后可能有图」预留一条编码通道，等于给自己留一个必然要处理的体积问题。
- **不做「导出成自解压 exe / zip」**：那需要本机编译或额外依赖，与「10 分钟复现」直接冲突（AGENTS.md §6）。
  HTML 是唯一的、任何机器都自带阅读器的格式。
- **不把时间线做成可折叠的交互**：这个文件可能被转发很多次，读者未必会去点。
  默认展开、只保留八类关键事件之后，长度已经可以接受（示例场次 20 行）。
- **不压缩体积**：示例场次打包出来 24 KB。为一个 24 KB 的文件引入 gzip 或裁剪，收益远小于「任何人打开都能看懂全文」。

## 后果

- 提交物多了一个可以单发的形态，「打包分享」成为界面上第一个对外传播的出口。
- 每一份打包文件自带隐私提示（里面有什么、分享前自己确认），因为它的用途就是被转发出去。
- 事件表里存的英文键名从此有了第二个消费者（界面 `STAGE_LABEL` 之外），
  两份映射需要同时更新——这是可接受的重复，因为它换来的是「服务端不必依赖 web 包的文案层」。
