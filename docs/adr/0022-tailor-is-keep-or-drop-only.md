# ADR-0022：一岗一版只做「留下 / 去掉」，一个字都不改

- 状态：接受
- 日期：2026-10-27
- 相关：ADR-0009（改写一律回到原文上重算）· ADR-0012（岗位要求三阶段）· ADR-0013（能现算的坐标不存第二份）· ADR-0018（版本对比按文本配对）

## 背景

同一份简历投不同岗位，用户真正缺的是一个判断：这个岗位看重的那几条，我写到了没有；
那些跟它无关的段落，是不是干脆去掉。整段改写的通道已经有了（反推建议 → 勾选采纳 → 改完的简历），
但它回答的是「这句话站不住，该改成什么」。缺的是另一个更轻的动作：**不重写，只决定去留**。

## 决策

1. **筛选是投影，不是编辑。** 输出文本等于原文按行取子集（去掉过行时把 3 行以上空行压成一个）；
   不调模型、不改一个字、不新增一句、不重排顺序。红线直接写在界面上。
2. **行级归属靠主张锚点算，不靠模型再判一次。** 一条主张的原文区间落进哪一行，就算那一行承载了它；
   采纳过改写时先把坐标按改动长度推到新文本上（改动区间与主张区间完全重合时直接用改后的长度）。
3. **「对得上」复用要求对照的结论，不另算一套。** 要求对照已经给每条要求判了答得上 / 答得含糊 / 简历里没写；
   筛的时候前两种算对得上，只有「简历里没写」不算——它是简历里压根没提的要求，没有哪一行可以去。
4. **一条主张都对不上就整版拒筛。** 返回原文，并在界面上说明「真按岗位筛，会把所有成果都筛掉；
   与其给你一份空壳，不如先补缺口」。用户点这个按钮的预期是「拿到一份更像投这个岗位的简历」，
   把成果全筛掉的东西不满足这个预期。
5. **还没有要求对照时返回原文。** 「这一场还没跑过岗位对照」与「一条都对不上」是两件不同的事，
   接口与界面都要能读出是哪一种（前者要回去跑一场，后者要补缺口）。
6. **筛过的文本一律不画锚点，按行重新切段。** 筛过之后坐标全变了，拿原文坐标去画引文高亮只会画错位置；
   宁可不画，也不画错。
7. **不落库，每次现算。** 文本、段数、去掉哪几条，都能从原文＋采纳记录＋要求对照推出来；
   三个导出文件（txt / 可打印 HTML / Word）都是当场算出来现发的。

## 取舍与代价

- **不按岗位重排顺序。** 重排要判断「哪一段更重要」，那是编辑判断，等于把改写的口子从后门开回来。
  真需要重排的人可以拿筛过的一版自己动手（Word 打开就是普通文档）。
- **一次只出一份。** 想投两个岗位就出两份、各自成文件；不做跨岗位合并版——一份文件同时讨好两个岗位，
  等于两个都没讨好。
- **段数按行计，不按语义段计。** 小节标题与没有主张的行都算留下的行，所以「留下 12 段」比用户直觉里的段落多。
  选行是因为界面上能逐行对上：用户点开原文自己就能数。
- **依赖上游跑过要求对照。** 没有对照的场次只能返回原文并写明原因，而不是自己猜一份匹配。

## 与既有决策的关系

- 与 ADR-0009 一致：一切改动都回到原文上用坐标重算，筛这一版也基于原文（原文或采纳改写后的文本）。
- 与 ADR-0013 一致：能现算的坐标与文本不落库——这一版连缓存都没做。
- 与 ADR-0018 分工：那个比较两场的判定，回答「改完是不是真的变好了」；
  这个不改判定，回答「这份简历投这个岗位，哪些段落是必要的」。
