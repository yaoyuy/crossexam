# ADR-0014：追问强度只换预算，不换人设

- 状态：已采纳
- 日期：2026-10-27
- 相关：ADR-0008（自建面试官也是契约）、ADR-0002（卡带按提示词指纹寻址）、`packages/shared/src/difficulty.ts`、`packages/shared/src/contract.ts`、`packages/server/src/orchestrator/panel.ts`

## 背景

A2 要的是「追问难度档位」：温和 / 常规 / 挑刺。最直觉的做法是给每档写一套不同的面试官人设——温和档换个友善的语气，
挑刺档换个更凶的人。但这个做法同时撞上两堵墙：

1. **人设进契约指纹**。换档等于换掉全场面试官的契约，跨场次「同一位面试官」的连续性就断了（后续按面试官看趋势的功能要靠它）。
2. **语气本来就管不住**。提示词里写「请更严厉一些」只是建议，模型听不听不由我们决定；
   而追问**次数**是我们能真正强制的——预算记账写在代码里（canProbe 五道闸门），不靠模型自觉。

## 决策

1. **档位只改预算三字段**：`maxRoundsPerClaim` / `maxProbesPerInterviewerPerClaim` / `maxTotalProbes`，
   温和 2/1/40 · 常规 3/2/60 · 挑刺 4/2/80。人设、目标、手法一个字不改。
2. **档位随会话落库**（`session.meta.difficulty`）。界面上它是投料台里的一个块，跑之前选；
   和阵容、运行模式一样，它是这一场的输入，历史会话读回来时按当时那一档显示。
3. **契约预算的收窄只留一处实现**。`contractBudgetView`（把 `BudgetConfig` 收窄成契约声明的三个字段）
   从 `panel.ts` 挪进 `shared/contract.ts`，避免两处各写一遍、算出两个指纹（F42 的教训）。
4. **卡带按档各录一套**。probe 提示词里带着预算数字，档位一换指纹就换，所以 48 盘卡带里有 24 盘是 probe（三档各自的轮次）。<br>现状（2026-10-27）：改写风格三档落成后共 **56 盘**，probe 仍是 24 盘；suggest 从 4 盘涨到 12 盘（4 条建议 × 三档风格）。<br>现状（2026-10-28）：版本对比落成后每组组合要连跑两场（改完再跑一遍），共 **149 盘**。

## 后果

- 好处：同一个面试官在温和档与挑刺档是同一个人，只是被允许问的次数不同——**题目变多，不是换人**。
- 好处：档位是硬的。实测温和档 2 轮 1 次、常规档 3 轮 2 次、挑刺档 4 轮 2 次，界面上契约卡片里的数字跟着变。
- 好处：换档真的换契约指纹（实测常规 042b385f → 挑刺 cf9c6457 → 切回又回到 042b385f），可解释、可对账。
- 代价：仓库里的 probe 卡带从 9 盘涨到 24 盘，总卡带 32 → 48；改一次 probe 提示词要重录三倍。
- 代价：历史会话的指纹要和当时的档位一起看，单看指纹看不出是「换了档」还是「改了契约」。
