# ADR-0034：小字号对比度基线，与弹层的键盘可达性

- 状态：已采纳（2026-11-08）
- 相关：ADR-0029（视觉令牌层）、docs/tech/06-limits.md

## 背景

评审用像素采样 + 令牌反查做了两处测量，都过不了 WCAG AA：

1. **小字号正文对比度不够。** 46 处 ≤12px 的文字用 `text-ink-500`：暗色底 `#4a6180` on `#080b10` = **3.11:1**，
   亮色 `#8b95a5` on `#f6f7f9` = **2.82:1**，都低于正文要求的 4.5:1；最差的是页脚 `text-ink-600` =
   **1.91:1**（暗）/ **1.79:1**（亮）。这些小字恰恰是「这个数字什么口径」「为什么值得问」这类解释性文字。
2. **四个弹层只有外观，没有键盘。** `HelpPanel` / `OnboardingWizard` / `InterviewerStudio` / `GrowthPanel`
   都声明了 `aria-modal="true"`，但全仓库 0 个 `keydown`、0 个 `.focus()`：
   Esc 关不掉、Tab 会跑到弹层背后、关掉之后焦点丢在 `body` 上。

## 决策

1. **小字号正文统一提到 `ink-400`**（暗 `#6f88a8` / 亮 `#5f6a7a`）：暗色 4.76–5.41:1，亮色 4.94–5.48:1，
   最差也是 4.76:1，过 AA。范围是**所有 ≤13px 的正文小字**（共 50 处，跨 18 个组件）；
   **纯装饰元素保留 `ink-500`**：chevron、`.nav-ico`、`.empty-art`、背景进度条——
   它们不承载文字信息，提亮反而摊平层次。
2. **新增共享 hook `packages/web/src/components/useModal.ts`**：模块级弹层栈（只有栈顶响应 Esc 与 Tab）、
   Tab/Shift+Tab 在弹层内首尾循环、打开时焦点落到第一个可聚焦元素、关闭时还焦点给触发按钮、
   body 滚动锁用计数（两层叠加时先关最上层，第二次 Esc 才关下一层）。四处弹层接线，
   **不改 `App.tsx`**（避免把可达性改动混进页面结构改动）。
3. **基线可复算**：对比度脚本读 `index.css` 的现成令牌算 WCAG 相对亮度，低于 4.5:1 直接 `exit 1`；
   另有 CDP 脚本在真浏览器里读实际渲染色 + 发真键验 Tab/Esc 行为（36 项断言）。

## 后果

- 暗/亮两套配色下，解释性小字都在 4.8:1 以上；深浅切换不再需要分叉（同一套令牌取反）。
- 弹层可以用键盘完全操作，且焦点不会丢——这是「评委用键盘点一遍」时才会暴露的问题。
- 已知残留：装饰性图标仍是 `ink-500`（暗色 2.74:1），按 WCAG 1.4.11 它是「非文本内容」、
  且都紧挨着文字标签，因此判定为装饰；若要严格对齐 3:1，把它们一并换成 `ink-400` 即可，无需改结构。
- 代价：界面上一处改动会同时动 18 个组件文件；这类「只换 token 类名」的批量改动必须在同一次提交里完成，
  否则会出现同一个界面里有的小字是 `ink-400`、有的是 `ink-500` 的不一致。
