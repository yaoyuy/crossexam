# ADR-0006：报告导出为三种形态，服务端不自己生成 PDF

- 状态：已采纳
- 日期：2026-10-26
- 相关：ADR-0001（服务端零构建）、ADR-0003（单端口托管前端）

## 背景

质询跑完，用户拿到的是屏幕上的一堆卡片。但一份报告真正的用途在屏幕之外：
发给同学看、打印出来对着改简历、贴进复盘文档。赛题评分里有「解题有效性与实用价值 25%」，
一个只能在线看的结论，价值会打折扣。

问题的难点不在排版，而在**谁来生成 PDF**。

## 决策

1. **服务端只出 HTML，不出 PDF。** 生成 PDF 意味着服务端要带一个无头浏览器
   （或一个 PDF 库），前者会把「10 分钟复现」变成赌评委机器上装了什么，
   后者要么是原生依赖（违反零原生依赖），要么自己造排版引擎（代价远超收益）。
   改成：服务端渲染一份**自带打印样式**的 HTML，`?print=1` 时页面 load 后自动调 `window.print()`，
   剩下的交给浏览器——用户按「另存为 PDF」即可，这条路在任何装了浏览器的地方都成立。
2. **Word 用「同一份 HTML + `.doc` 后缀 + `application/msword`」。** 这是 Word 至今仍认的老格式，
   零依赖、可编辑、打开即排版。代价是没有 `.docx` 的严格结构（见「代价」）。
3. **三种形态同源。** `renderReport`（Markdown）与 `renderReportHtml`（HTML）吃的是同一个 `SessionView`，
   章节顺序一一对应（过程说明 / 主张与判定 / 追问实录 / 修改建议 / 复现方式），
   谁也不会多出对方没有的结论。
4. **不复用 `tools/docs/md2html.mjs`。** 那个渲染器服务于技术文档（工具目录、只认 Markdown 子集），
   而报告需要锚点引用块、判定配色与打印分页控制——它是产品的一部分，不是文档工具的一部分。
5. **HTML 报告不引用任何外部资源**（无 CDN、无字体文件、无脚本外链），
   保存单文件即可离线打开；页脚写明「简历与报告都没有离开这台机器」。

## 备选方案

- **服务端用 headless 浏览器出 PDF**：能得到最漂亮的 PDF，但把复现前提从「装了 Node」变成
  「装了 Node 且能找到浏览器」，与 README 的十分钟承诺冲突。
- **引入 `pdfkit` / `puppeteer`**：前者是纯 JS 但需自己排版分页，后者是原生依赖。均被零依赖约束挡下。
- **只提供 Markdown**：携带性最好，但评委/用户第一眼看到的是带 `#` 和 `|` 的原文，
  而这份产品的评分项里有「用户体验与产品精细度 15%」。

## 代价与边界

- `.doc` 不是 `.docx`：复杂排版（页眉页脚、目录域）不会有。改简历用足够了。
- PDF 的最终样式取决于浏览器（本机实测 Edge 打印为 6 页 A4）；
  服务端保证的是内容与分页提示（`.claim` / `.probe` / `.advice` 不跨页断开），不是像素级版式。
- 打印脚本只在 `?print=1` 时注入：默认打开 HTML 报告不会突然弹打印对话框（有测试守住这一点）。

## 验证方式

- `packages/server/test/http.test.ts`：HTML 报告 200 / `text/html` / 含判定中文与锚点引文；
  不带参数不含 `window.print()`，`?print=1` 含；`.doc` 的 content-type 与附件名；未知会话 404。
- `packages/web/test/report-urls.test.ts`：三个网址形状与会话编号转义。
- 真机验收（`.tmp/report-check.mjs`，12/12 通过）：服务端 HTML 经 Edge 打印得到 438305 B / 6 页 PDF；
  真界面上三个按钮的 href 分别指向 `report.md` / `report.html?print=1` / `report.doc`。
