# ADR-0025：判定台账是一张平表，不是又一份报告

- 状态：已采纳（2026-10-28）
- 相关：ADR-0019（历史仪表盘只做聚合）、ADR-0020（单文件打包）、ADR-0013（补充说明不落坐标）、ADR-0007（导入通道与依赖纪律）

## 背景

报告是给人**读**的：它有章节、有叙述、有取舍，读着顺。可用户真正要拿它做的事是**逐条改简历**——
按类别看哪一类最欠证据、按追问次数看哪一条被问得最狠、把被代码拦下的看看工具丢过什么。
这三件事在 Markdown 与 PDF 里都很难做：不能排序，不能筛选，也不能只留下「证据缺失」那几行。

所以第 11 条要求的候选清单里留了一件「判定台账导出 Excel」。它是这份工具的第五种带走方式，
而且它与其他四种不是同一类东西：报告与打包是**阅读**，台账是**加工**。

## 决策

1. **台账是投影，不是第二套判定。** 一行一条主张，所有列都来自库里已经算好的东西
   （`view.claims` / `view.probes` / `view.verdicts` / `view.suggestions` / `view.requirementMatches` /
   `view.rejectedClaims` 等），`ledger.ts` 只做取值与排版，不新增判定、不重新解释口径。
2. **五张表固定**：「这一场 / 判定台账 / 追问明细 / 岗位对照 / 被拦下的」。
   最后一张是刻意留的——被拦下的主张、要求与反问是这套工具**做过的减法**，报告里写一句话说不清，表格里能数出来。
3. **自己写 .xlsx，不引第三方库**（也不引 `exceljs` / `xlsx`）：与 ADR-0007 砍掉老 `.doc` 同一个理由——
   少一个依赖就少一个复现失败点，而这里要产出的东西很窄：几张只有表头和纯文本的表，不要公式、样式与图表。
   OOXML 能被打开的最小集合是固定的五份 XML（`[Content_Types].xml` / `_rels/.rels` / `xl/workbook.xml` /
   `xl/_rels/workbook.xml.rels` / `xl/styles.xml`）加一个 zip 容器。
4. **zip 时间戳写死 1980-01-01**：同一场两次导出逐字节相同。否则每导一次，版本库里就会多出一个
   「变了但其实没变」的二进制文件，而这类噪声会让真正的内容改动淹没在 diff 里（与卡带、演示数据的同一条纪律）。
5. **服务端现算，不落库**：睡得着的坐标不存第二份（ADR-0013 同一取舍）。台账不是新数据，是新视图。
6. **界面只有一颗入口**「台账 Excel」，出现条件与「打包分享」完全相同（有会话且有主张）；
   入口挂在头部同一排，用户不必记住它是哪一种导出。
7. **表内行序跟报告一致**（主张按编号、追问按编号、要求按编号）：同一个人拿着一份报告与一份台账时，
   两边的第 3 行说的是同一件事，不用靠猜。

## 取舍

- **不做样式、条件格式、公式、冻结以外的窗口**：写入器只保证 Excel 打得开、内容读得回来、结果确定。
  想画图表那是用户自己在 Excel 里的事；我们的责任是把事实摆平。
- **超长单元格截到 32000 字符**（Excel 上限 32767）：宁可截断，也不要生成一个打开就报损坏的文件。
- **不塞图片、不塞附件**：那是单文件打包（ADR-0020）的活。台账只装能排序的文本与数字。
- **不进 LLM**：台账一个 token 都不花，也因此不会因为模型换了版本而变化——它是一份可以归档的证据。

## 代价与验证

- 代价：多了一个需要自己维护的文件格式（约 290 行；这个项目本来就有只读的 zip 解析器，写入这半边独立放着，两者互不依赖）。
  格式对不对不靠自述，靠两条断言：仓内的 `readZip` 解得回来（`packages/server/test/ledger.test.ts`），
  以及用 `openpyxl` 交叉读一次（实测五张表都在、判定台账 6 行 × 13 列、中文逐字正确）。
- CRC 必须按标准多项式算：测试直接拿公认向量对（`crc32("123456789") === 0xCBF43926`），
  因为写坏的 CRC 在自家解析器上照样读得出来，只有对方的解压程序会报错——那种失败发出去之前谁也看不见。
