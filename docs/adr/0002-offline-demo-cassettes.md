# ADR-0002 离线演示走脚本合成卡带，并用漂移门禁守住它

- 状态：已采纳
- 日期：2026-10-26
- 相关：ADR-0001、提交物 #3「README 10 分钟极速复现指南」、packages/server/src/llm/scripted-demo.ts

## 背景

评分里 25% 是「过程可复现性」，提交物要求一份 10 分钟极速复现指南。
本项目的核心体验是多 Agent 对抗式追问——如果评委员没有 API Key，默认模式下点一次
「示例简历」就该看到完整的一场质询，而不是一句「请配置环境变量」。

同时我们有一条隐私红线：真实简历内容只落本地 SQLite，不上传第三方，也不进公开仓库。
这两条约束合起来意味着：**演示素材必须是合成的，且不能依赖联网**。

## 决策

1. **默认模式是 replay**（CROSSEXAM_MODE 缺省即 replay），卡带放在仓库的 fixtures/llm/。
2. **演示卡带由脚本合成**（packages/server/src/llm/scripted-demo.ts）：一份写死的剧本，
   按**真实提示词**渲染回答，再按提示词指纹（sha256 前 24 位）落盘。
3. **合成数据必须一眼可辨**：卡带里的 model 字段固定为 scripted-demo，
   recordedAt 固定为一个常量（因此重跑逐字节相同），且 fixtures/README.md 明写这一点。
4. **生成器自检**：录完立刻换只读回放客户端在另一个内存库里重跑一遍，
   比对两次结果签名（主张、追问链、判定、建议、通知、预算、用量）；
   另外逐阶段点名 extract/probe/answer/verdict/suggest 是否都录到，缺一即退出码 1。
5. **漂移门禁**：packages/server/test/demo-cassette.test.ts 用**仓库里已提交的卡带**
   走真实 HTTP 跑一遍完整沙盘。改了提示词而没重跑 npm run seed:demo，这条测试就红。

## 后果

**收益**

- 评委零配置、零联网、零 Key 就能看到完整产品流程，复现步骤里不存在「先申请 Key」。
- 演示是可重复的：同一份卡带每次跑出的判定与追问完全一致，录视频不用碰运气。
- 卡带指纹只由提示词内容决定（不含模型名），换模型不会让整盘失效。
- 卡带本身就是「意图控制」的证据：每个 Agent 的 System Prompt 原文都在卡带里躺着。

**代价**

- 提示词一改就要重跑 seed:demo，否则离线演示会在那一阶段报「找不到记录」。
  用漂移门禁把这条纪律变成 CI 事实，而不是靠人记得。
- 合成回答的**质量**取决于剧本作者的判断，不代表真实模型水平。
  因此 usage 是估算值（按字符数折半），且卡带必须自曝身份，不得冒充真实输出。
- 拿到真实 Key 后若要用真实卡带替换，需要同时更新 fixtures/README.md 的说明，
  否则读者会分不清哪批是合成的。

## 备选方案

- **默认 live，无 Key 就报错**：把「第一步就失败」当作对评委的交代，等于主动放弃复现分。
- **提交时录一批真实模型卡带并冒充演示数据**：可复现性更强，但一旦未标注就构成误导；
  而且真实卡带的稳定性依赖当时模型版本，回放内容与代码内提示词脱节时无自动告警。
- **只做录屏视频，不给可跑的离线路径**：视频无法被评委独立验证，过程分拿不满。
