# ADR-0027：界面按任务分页，而不是把所有东西堆在一屏

- 状态：已采纳（2026-10-28）
- 相关：ADR-0003（前端独立成包 + 单端口）、ADR-0010（零安装启动器）、ADR-0028（桌面端用浏览器应用窗口）

## 背景

P3 起的界面是「一屏塞完全部」：投料、阶段轨、结论、原文四栏并排，历史会话列表挤在左栏底部，
报告的五种导出挤在头部，面试官工作室与岗位模板库各占一块浮层。功能长到 P12 之后，
这一屏承担了太多职责，新手第一次打开不知道从哪下手；用户提出「做成桌面软件那样，左边一列，一页一件事」。

## 决策

1. **六个页**：首页 / 投料台 / 质询台 / 报告 / 历史 / 设置（`packages/web/src/pages.ts` 的 `PageId` / `PAGE_ITEMS` / `pageOf`），
   左栏常驻导航，`#/report` 这类哈希深链可以直接进到某一页。
2. **每页只管一件事**：投料台贴材料（岗位模板、简历与 JD 导入、运行模式与阵容）、质询台看这一场
   （阶段轨 + 三块结论 + 原文与改写）、报告页只列五种带走方式、历史页只做概览与列表、
   设置页放配色 / 向导 / 隐私 / 启动与桌面。旧的多栏布局不是删掉，而是**拆到各页**。
3. **页面状态放 URL 哈希，不引路由库**：只有六个平级页、没有嵌套路由与参数，`location.hash` 足够；
   每多一个依赖就多一个「评委机器上装不出来」的失败点（与 ADR-0007、ADR-0025 同一条纪律）。
4. **「这一场」不跟着页面走**：会话 id 仍由 `useSessions` 持有，切页不丢；切到别的页再回来，直播接着看。
5. **宽屏质询台仍是三列，但外层带 `xl:h-full`**，三列各自滚动。少了这个约束，三栏会各自长到内容那么高、
   整页变成一个长条（也是 06/07 两张截图逐字节相同的原因，见 F92）。
6. **多步向导取代「首开自动弹教程」**：`packages/web/src/help.ts` 的 `WIZARD_STEPS`（五步）与
   `crossexam.seen-wizard`；走一步就把背景切到对应那一页，走完或跳过都不再弹。教程改成从按钮打开——
   首开自动弹层会打乱所有浏览器脚本（F38）。

## 取舍

- **不做「单页内切标签」**：那只是把同一屏换个摆法，导航仍然是「一页一件事」。
- **不用 react-router**：见决策 3；代价是深链只支持页级，不支持「第几场会话」这种参数化地址。
- **代价是「一屏看全」变成「多页来回切」**：所以向导每一步都把背景切到对应页，用户不必自己记「报告在哪一页」。
- **截图与点测脚本必须一起重写**（30 张图、177 项断言）：旧的「一屏塞六件事」断言在分页后必然超时。
  测试与界面同源，这一笔成本是必须付的；反过来说，点测全绿也证明了分页没有把功能弄丢。
