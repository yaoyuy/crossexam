# ADR-0015：反问必须锚回原文，模拟的回答必须标注是模拟

- 状态：已采纳
- 日期：2026-10-27
- 相关：ADR-0009、ADR-0012、`packages/shared/src/counters.ts`、`packages/web/src/components/CounterBoard.tsx`、`packages/shared/src/domain.ts`

## 背景

A4「轮到你了」：跑完一场之后，给用户几句可以拿去反问 HR 的话，每句都带原文依据，并附上「对方大概会答」。

这个功能有一处真实风险：用户可能真的拿着这几句话去面试。其中岗位要求与简历原文是**可验证的**（锚点锚得住），
但「对方大概会答」是模型按人设模拟出来的——不是任何真实 HR 说过的话，也不是这家公司的真实情况。
如果界面上把两者混在一起排版，用户会把模拟出来的回答当成情报，那这个功能从帮忙变成误导。

## 决策

1. **反问的产物也是锚定对象**。`groundCounters` 要求每句反问带一个 sourceId，只能指向 1–8 份 JD 之一或一条简历主张；
   `quote` 必须能在那份材料里逐字（或归一化）锚住。锚不住就进 `rejected`，界面上单独一个折叠块写清理由。**没有依据就不生成反问**。
2. **依据来源必须显式标注**。每句反问标「依据岗位要求」或「依据简历原话」；
   引文按钮点下去在对应栏聚焦到那一段（复用既有焦点机制，JD 一侧走 `handleFocusJd`）。
3. **模拟的回答必须在界面上标注**。`CounterQuestion.reply` 是模型代答，界面每条都写「（沙盘模拟，不是真 HR 在答）」，
   报告里也写明回答由沙盘里的求职者 Agent 代答。
4. **反问不参与判定**。它不改变任何主张的 verdict，也不进短板统计；它只是把「你还能问什么」摆出来。
5. **缺失清单不生成反问**。`jd-match` 判成「简历里没写」的要求不进反问域，理由同 ADR-0012 第 2 条——
   不拿简历里没提的事去问，也就不拿它去反问。

## 后果

- 好处：功能扩展没有引入新的锚定机制，`resolveAnchor` 第三次被复用（简历 → JD → 反问）。
- 好处：「哪一句可以拿去面试用、哪一句只是沙盘里演给你看的」在界面上分得清，这是这个功能能被信任的前提。
- 好处：锚不回的反问不是被静默丢掉，而是进 `rejected` 并写明理由——被拦下的东西同样是可展示的产物。
- 代价：又一个阶段（第九个），又一次全部卡带重录（48 盘里新增 1 盘 counter）。<br>现状（2026-10-27）：共 **56 盘**，counter 仍是 1 盘。<br>现状（2026-10-28）：共 **149 盘**，counter 仍是 1 盘。
- 代价：schema v9 多一张 `counter` 表；改一次 counter 提示词就要重录这一盘。
