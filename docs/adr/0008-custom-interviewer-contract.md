# ADR-0008：自建面试官的产物是契约，不是一段自由文本

- 状态：已采纳
- 日期：2026-10-26
- 相关：ADR-0002（离线卡带）、ADR-0005（阶段路由）、`packages/shared/src/interviewer.ts`

## 背景

用户第 4 条要求（m04531）：「不能只有技术面试官，要能在页面里自己设置面试官，
并通过 API 对自己的面试官契约进行优化，要求所有专业的人都能用」。

最省事的做法是让用户填一段 System Prompt 自由文本，直接发给模型。但那会把这个项目最值钱的东西丢掉：

1. **不可解释**：自由文本没有结构，界面没法把「人设 / 目标 / 手法 / 禁区 / 共同约束 / 追问预算」摊开给评委看；
2. **不可版本化**：改一个字就是另一份提示词，却说不出改了什么——「AI 改了什么」的 diff 无从生成；
3. **不可对账**：契约指纹（`contractDigest`）是对账「界面显示的」与「送进模型的」是否为同一份的唯一手段，
   自由文本算不出稳定的指纹；
4. **不可约束**：共同约束与禁区（无锚点不许提问、不许编造引文）是写死在契约里的，自由文本会绕开它们。

## 决策

1. **草稿是窄字段结构**：`InterviewerDraft`（名称 / 领域 / 资历 / 语气 / 简介 / 目标 / 追问手法 2–5 条），
   由 `interviewerDraftSchema` 校验。模型返回的 JSON 必须过这道门，过不了就不收。
2. **草稿补成同一份 `IntentContract`**：`buildCustomContract` 复用 `COMMON_CONSTRAINTS` / `COMMON_FORBIDDEN`，
   `persona.role` 置为 `'custom'`。于是渲染（`renderSystemPrompt`）、指纹（`contractDigest`）、对账全部复用既有代码，
   自建面试官与五位预设**在系统眼里没有区别**。
3. **落全局库，但冻结在会话里**：`interviewer` 表存 `id + version + digest + contract_json`；
   一场会话引用某位自建面试官时，把 `id + version + digest` 写进 `meta.panel`。之后在库里改或删，
   旧会话的复现与对账仍然成立——历史不可被追改。
4. **预设不可改、不可删**：它们的人设写在代码里。允许改等于允许悄悄改历史。

## 后果

- 好处：「任何专业都能配自己的面试官」与「意图可解释、可版本化、可 diff」这两件事不冲突，
  自建面试官同样能在界面上摊开契约、看指纹、看渲染出的 System Prompt。
- 代价：用户不能随心所欲地写任意提示词，只能在 7 个字段里表达。这是刻意的取舍——
  结构换来了可解释与可对账，而自由文本换来的只是「更像 ChatGPT」。
- 代价：库里多一张全局表，多一条「会话引用了被删掉的面试官怎么办」的边界（会话照跑，用冻结的那份；
  界面在阵容里标出「已从库里删掉」）。
