# ADR-0023：把「在别人机器上还成不成立」也管起来

- 状态：已采纳（2026-10-27）
- 相关：ADR-0001（服务端零构建）、ADR-0010（零门槛入口不做 exe）、ADR-0014 / ADR-0017（卡带指纹）、ADR-0020（单文件打包）

## 背景

门禁一直只有本地一道：`npm run verify`。它证明「在这台机器上、以我的环境为准」是绿的，证明不了两件评委一定会遇到的事：
① 干净检出（Linux、没有我的 Edge、没有 `D:/CZB` 这个路径）还能不能跑；② 提示词改过之后，`fixtures/llm` 里的卡带是不是已经和当前代码脱节——
脱节的表现不是构建失败，而是评委点按钮时看到报错。此外「十分钟复现」里的耗时与体积一直只有人工实测，没有任何门禁看着它们。

## 决策

1. **CI 只补本地跑不出来的那一半。** 本地已有的门禁（typecheck / 单测 / 冒烟 / 构建 / 性能预算）不在 CI 里另写一套命令，直接跑 `npm run verify`——两处各写一份清单，迟早出现「本地绿、CI 红」且无法判断哪边才算数。
2. **漂移门禁用「重跑 + `git diff`」实现，不另写比对工具。** `npm run seed:demo` 是逐字节确定的（合成客户端固定 model 与时间戳、提示词里没有时间与随机数），所以 CI 里跑一遍再 `git diff --exit-code -- fixtures/llm` 就够了：有差异就是「改了提示词忘了重录」。好处是没有第二套事实要维护，代价是它要求 seed 永远保持确定性。
3. **性能预算的阈值按数量级定，不按最近一次实测定。** 同一段代码两次启动测出 1739 ms 与 285 ms（冷热差 6 倍）。按实测值加余量定阈值，红灯反映的是机器在忙，不是代码变慢。所以每项都定在数量级上（整场回放 8 秒而不是 0.1 秒、JS gzip 128 KB 而不是 106 KB），只拦数量级上的变坏。
4. **性能预算进 `verify`，因为它只要几秒。** `npm run budget` 起临时服务、用回放模式跑完一场再量体积，本机约 3 秒。能进主门禁的东西就不要另开一道容易被忘掉的命令——与 ADR-0003 的单端口取舍同源。
5. **点测拆成独立的 `browser` job（windows-latest）。** 点测要真浏览器与真服务，Linux runner 上装 Edge 的收益远小于成本；而它需要的能力（Windows、Chromium 内核）恰恰与开发机一致。
6. **让门禁可搬，先把写死的路径去掉。** `tools/ui-e2e/e2e.mjs` 原来把卡带目录写死成 `D:/CZB/fixtures/llm`、把浏览器写死成本机 Edge 路径。前者改成从模块位置反推仓库根，后者改成候选列表 + `CROSSEXAM_BROWSER` 环境变量覆盖，候选全都不在才报错。
7. **CI 里额外跑一次 `npm run stats` 只为留痕。** 代码规模不设阈值（它会随功能增长），但每次都打印在日志里，翻历史时能与技术文档那张表对上。

## 取舍

- **不追求「CI 全绿」本身。** CI 不是质量，它只是「换台机器还成不成立」这个问题的机器化答案。本地门禁更严格（多一道单端口真进程冒烟），CI 上跑的就是本地那一套。
- **`gate` 与 `browser` 两个 job 不做依赖。** 点测要的产物（前端构建）由它自己构建，互不阻塞；代价是多花一次 `npm ci` 与一次构建的时间。
- **性能预算不量 LLM 调用。** 联网耗时取决于服务商，不是这个仓库能承诺的东西；14 项量的全是本地可复现的部分（起服、回放、报告、打包、体积）。
- **不引入第三方 CI 服务或性能平台。** 理由是 AGENTS.md `6：任何需要额外账号或本地编译的东西都会毁掉「十分钟复现」；而这份工作流文件本身是可读的，复制到任何支持 GitHub Actions 的仓库都能用。

## 与既有决策的关系

- ADR-0001（服务端零构建）：`gate` 直接在 Linux 上跑 TypeScript 源码，验证的就是零构建这条地基在别人的机器上同样成立。
- ADR-0014 / ADR-0017（卡带按提示词指纹寻址）：漂移门禁正是这条设计的自动守卫——指纹变了但没有重录，diff 立刻非空。
- ADR-0020（单文件打包）：打包的体积上界与「不许有外链」在性能预算里各有一条断言，同一个约束同时被两种门禁看着。
