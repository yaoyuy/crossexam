# 演示视频脚本（5–8 分钟 · 1080p）

> 赛题要求：5–8 分钟、1080p，**其中至少 2 分钟是 AI 协同过程复现展示**。
> 这份脚本把 2 分钟以上留给了第四节，并在第五节给出「录像时照着念」的段落划分。

## 零、录制前的准备（10 分钟）

| 项目 | 做法 | 为什么 |
| --- | --- | --- |
| 环境 | `npm run preview`（构建 + 起服），浏览器全屏 1920×1080，隐藏书签栏 | 一条命令起完整产品，避免录到开发中的半成品 |
| 数据 | 一律用内置示例简历（「一键示例」按钮） | 真实简历是隐私数据，不上镜头也不进仓库 |
| 节奏 | 左栏节奏选「慢放」 | 慢放只影响播放节奏，不改变任何结果；即时模式下追问是瞬间刷出来的，观众看不清 |
| **密钥** | **不要录 live 演示**；若必须录，先 `clear` 并把终端字号调小，或用 `.env` 而不是内联环境变量 | 屏幕录像里出现一次 API Key 就等于公开泄露 |
| 通知 | 系统勿扰模式 + 关闭微信/浏览器通知 | 一条弹窗就要重录 |
| 录制 | Windows：Win+G（Xbox Game Bar）或 OBS；分辨率固定 1920×1080，帧率 30 | 1080p 是硬要求 |

## 一、开场：问题（0:00–0:45）

**画面**：左栏空状态（截图 01-intake），四条核心机制与行业模板库并列可见；第一次打开会先弹出新手教程（截图 12-help），点掉它再开始。

**旁白**（照念即可）：

> 简历上这句话——「主导重构订单系统，首屏加载从 2.4s 降到 0.8s」——
> 如果面试官追问「2.4 秒是怎么测的？在什么设备和网络下？取的是均值还是 P75？」
> 你答得上来吗？
>
> 大多数简历工具解决的是「怎么写得好看」；CrossExam 解决的是另一个问题：
> **这句你写上去的话，扛不扛得住追问。**

## 二、现场演示：一场真实质询（0:45–2:00）

| 时间 | 动作 | 观众看到什么 |
| --- | --- | --- |
| 0:45 | 点「一键示例」 | 简历与 JD 进入投料台 |
| 0:55 | 点「开始质询」 | 阶段时间线开始推进：抽取 → 读岗位要求 → 组庭 → 追问 → 判定 → 反推 → 轮到你了 |
| 1:05 | 停在追问进行中 | **三位面试官同时追问**，左栏「实时输出」逐字显示模型正在写什么 |
| 1:20 | 点卡片里的引文 | 右栏简历原文滚动到对应片段并高亮（截图 06 / 07） |
| 1:40 | 等判定出现 | 每条主张拿到一个判定：站得住 / 表述过度 / 证据缺失 / 与原文矛盾 / 无法回答；左栏同时按类别汇总短板 |

**旁白要点**：

- 「注意，每一次提问都带着简历原文的逐字引文，没有引文的提问会被前端拒绝渲染。」
- 「实时输出里的字是模型正在写的原文，它**不进事件日志**——能断线续传的只有阶段事件。」

## 三、判定与反推：结论是怎么被程序兜住的（2:00–3:30）

## 四、AI 协同过程复现（3:30–5:40，**≥2 分钟**）

这一节是评分表里 25% 的过程分，也是赛题点名要求的部分。**画面切换为仓库里的 Prompt 链快照**
（`docs/prompt-chain/` 下 34 份文件、其中 30 份分片，由 `npm run export:prompt` 从会话日志自动导出，不是事后补写的）。

### 4.1 迭代一：证据锚定为什么不信模型给的坐标（3:30–4:05）

- 展示 Prompt 链里那次对话：让模型返回 `start/end` 偏移量 → 实测发现模型**常常把坐标算错却把引文抄对**。
- 展示决策记录 D7 与代码 `packages/shared/src/anchor.ts`：坐标一律以引文回原文重新定位为准，模型的偏移量只当提示。
- 一句话总结：「**锚定是地基，不是加权项。**」

### 4.2 迭代二：用户一句话带出的真 Bug（4:05–4:45）

- 展示那次对话：用户给出 API Key 并说「整体过一遍流程，跑一遍看看能不能用，测试每一个功能，还有整体核一遍代码」。
- AI 真跑一场后报出 9 条一模一样的 `claimId: Required`——提示词从没要求模型输出 claimId，而 schema 却把它设成必填。
- 关键点：「**离线演示与单测一路全绿**，因为合成夹具恰好写了 claimId；只有真联网跑才暴露。」
- 对应提交 `c8a6e90` 与 findings F23，并补上回归测试「模型不返回 claimId 也能出建议」。

### 4.3 迭代三：并发追问撞出的唯一约束（4:45–5:10）

- 展示真模型一轮对同一条主张给了两条追问 → 撞上追问表的唯一约束 → 整场事务回滚、接口 500。
- AI 的处理：schema v3 去掉该约束，迁移步骤冻结在自己时点；去重改由 `probe.ts` 的 seenQuestions 负责。
- 一句话总结：「**数据库约束只能描述业务上真的不可能出现两条的情形**，不能用见过的数据形状去定约束。」（决策 D20）

### 4.4 迭代四：验证手段本身也要被验证（5:10–5:40）

- 展示「同进程接口测试全绿，真起服务第一次写入就报 `no such table: session`」这条事故（findings F11）。
- 处置：门禁加入**真进程冒烟**（`npm run smoke`，9 项），并把「连接即建表」设成默认路径。
- 收尾话术：「四次迭代，四次都是**先有证据、再改代码**；Prompt 链快照让这条链子在事后仍可逐字回放。」

## 六、结语（7:00–7:20）

> 这个项目没有做「帮你写简历」——那是另一个已经有很多人在做的方向。
> 它做的是**在你投出去之前，先把它拷问一遍**。
> 而且这个「拷问」的过程，每一步都能被审计：提问有锚点，追问有预算，判定有收敛，过程可回放。
