# docs/screenshots —— 界面截图（由命令生成，不是手点的）

    npm run build && npm run shots

生成器是 [tools/ui-shots](../../tools/ui-shots/README.md)：真起服务、真起浏览器（系统 Edge/Chrome，走 CDP）、
按 `data-shot` 锚点走完一遍操作，顺便把控制台报错当失败。也就是说这批图随时可以重新生成，
而不是「上次截的图」——README、技术文档、演示视频封面都用它们。

16-studio.png 里的「医护面试官」是用**本地规则**生成的（不联网、确定性），存下来的自定义面试官与五位预设共用同一套契约结构、
同一套渲染与指纹逻辑——这是「任何行业都能配自己的面试官」那条要求最直接的证据。

其中 04-live-output.png 与 05-thinking.png 是**回放模式**下拍的（`npm run shots` 为了零 Key 可复跑，一律用示例卡带）：
分片由回放端按 24 字软切生成，思考那一行来自合成脚本写在卡带里的 `reasoning` 字段。真实联网下同一栏由 SSE 的 `event: stream` 填充：
正文分片来自模型输出，思考分片来自思考模型的 `reasoning_content`——2026-10-26 实测一场 5814 片正文 / 2355 片思考 / 8 路 `verdict:*` 通道，且分片都不进事件表（见 docs/adr/0004、docs/adr/0005、findings F22）。

所有画面用的都是内置示例简历（合成素材），不含任何真实个人简历。
