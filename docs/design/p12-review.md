# P12 设计评审：成长档案（②）与一岗一版简历（③）

> 按 AGENTS.md 第 7.1 条：开工前先给一页评审。本页写清「解决谁的什么问题 / 怎么做 / 风险 / 怎么验收」。
> 评审通过后动代码；越界改动重新评审。

## 一、这次要解决什么

C1 只比**相邻两版**，C2 只给**跨场次的合计数**。两者之间缺一层：

1. **改了三次，同一句话还在被打回**——现在看不出来。C1 只能告诉你「这一版比上一版」，
   而真正让人下决心改简历的，是「这一条我改了两回，第三回还是被判证据缺失」。（②）
2. **同一份简历投不同岗位，要改的地方不一样**——现在只能手动核对要求清单，一条一条去简历里找。（③）

这两件事都**不需要模型**：② 是同一批判定换个时间维度看，③ 是同一份原文做选择与排序。
这是本批最重要的性质——**不动提示词、不重录卡带、离线回放的承诺一寸不退**。

## 二、两项的做法与验收

### ② 成长档案：一条主张在几个版本里的判定轨迹

- **链路从哪来**：沿 `session.parent_session_id` 往上走（C1 已经落好的版本链），不按 `resumeHash` 猜。
  理由与 C1 的「显式版本链」一致：采纳改写之后简历原文必然变了，指纹认不出亲。
- **怎么做**：新建 `packages/shared/src/growth.ts`，纯函数。输入一串按时间排好的场次
  （每场只有 `claims` 与 `probes`），输出三样东西：
  - `points`：每一版一行（已判几条、站得住几条、追问几次）——这就是能力曲线的点；
  - `trails`：把**相邻两版**用 C1 的 `alignClaims` 牵一次，再把「上一版的某条 ↔ 这一版的某条」连成链，
    一条链就是同一句话的判定历史（哪一版出现、哪一版消失、每次判成什么、相对上一次是变好还是变差）；
  - `persistent`：**改过还在被打回**的那些链——出现 ≥2 版，且最近一次判定不是「站得住」。
    这是整个功能的重心：只报一个数字没有意义，要能点回原文。
- **服务端**：`GET /api/sessions/:id/growth`，从这一场往上走到根，把每场的 `listClaims` / `listProbes` 攒起来交给纯函数。
  链断了（父会话被删）就停在那里，并在返回里说明「第 N 版之前的那一版已经删了」——不假装连续。
- **界面**：抽屉（与新手教程、面试官工作室同一种浮层），不动四栏布局。
  入口两个：头部一颗「成长档案」，以及「比上次」栏里那句「这是第 3 版，看全部 3 版」。
- **风险**：低。只读、不调模型、不动 schema。真正的风险是**把「同一句话」认错**——
  相似度配对是启发式的，所以链上每一步都要能点开看原文，不能只给一条漂亮的曲线。
- **怎么验收**：shared 单测（一版 / 两版全变 / 改写后仍认得出来 / 中间一版消失又回来 /
  「改过还在被打回」的判定口径 / 入参顺序打乱结果不变）；服务端一条端到端（真跑三版，链走通、断链有说明）；
  e2e 一条（打开抽屉、三版都在、数字与接口一致）。

### ③ 一岗一版简历：按岗位挑出该留的那几条

- **怎么做**：新建 `packages/shared/src/tailor.ts`，纯函数，**不调模型**。输入是简历原文 + 结构化切分 + 主张 +
  岗位要求对照结果，输出**一份新的简历文本**：被这个岗位的要求命中（`hit` / `weak`）的主张所在的原文行留下，
  与任何要求都无关的行也留下（不能因为岗位没提就把教育背景删了），**一个字的表述都不改**。
- **排序**：留哪些由对照结果定，不改写；同一小节内保持原文顺序（打乱顺序等于重写了一遍简历）。
- **导出**：复用现有 HTML → PDF / Word 通道，多三个地址 `tailored.txt / .html / .doc`；
  不新写渲染器，只多传一份文本（与 C3 的教训一致：同一件事不要两套渲染）。
- **界面**：岗位要求栏每份 JD 旁边一颗「按这个岗位出一版」，出完在右栏与改完的简历并排可选（原文 / 改完的 / 这一版）。
- **风险**：中。风险不在技术，在**它长得太像「按 JD 装饰简历」**。
  所以红线写在界面上：这一版只做「留下 / 不留下」，不新增任何一句、不改任何一个字、
  并且每条留下的主张旁标注它靠哪条要求留下——没人被要求相信一个黑箱。
- **怎么验收**：shared 单测（无 JD 时原样返回 / 命中行留下、无要求行留下 / 完全没命中时给出清楚的空态）、
  服务端一条（三份 JD 各出一版，字数与留下的主张数对得上）、e2e 一条（换 JD 后停在这一版的文本确实变了）。

## 三、顺序与判断

**② → ③**。② 只读、只加一个纯函数与一个接口，当天能验收；③ 要碰导出的三种形态（有回归风险），放后面。
两项之间互不依赖，也都不依赖新的模型能力。

## 四、两处默认选择（不同意就改）

1. **成长档案用抽屉，不新开一栏**。四栏在 1600×1000 下刚好，加第五栏要么挤、要么让每一栏都变窄；
   而这个功能是「偶尔回看一次」，不是常驻视角。
2. **一岗一版只做「选与排」，不做「改写」**。改写已经由 `suggest` 通道负责（有锚点、有数字闸门、有三档风格）。
   让两条路径都能改同一句话，等于给「简历里为什么会多出一个数字」留两个入口——这是 F27 那类事故的温床。

## 五、这一批不动什么

- 不动提示词 → **卡带指纹不变，不重录**（149 盘照旧）；
- 不动 schema（版本链 v10 已经在，`tailored` 是现算的，不落库）；
- 不动四栏布局，不加第五栏；
- 不做英文简历（D2 已定不做）。
