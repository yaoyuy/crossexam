# 新会话启动单（防上下文跑满）

> 起因：2026-10-28 的主会话跑到第 41 轮时，下一次请求要带 8.0M tokens，
> 网关直接 413（`Exceeded limit on max bytes to request body: 16777216`），整轮报废。
> 结论只有一条：**状态必须落盘，不能只活在对话里。**

## 一、新会话第一句话（照抄，不用改）

```
先读盘再动手，不要我复述：
1. task_plan.md 全文（目标、硬性交付物、阶段表）
2. progress.md 最后 120 行（上一个会话干了什么、门禁数字、没动的东西）
3. findings.md 最后 80 行（踩过的坑，编号 F<N>）
4. git log --oneline -10 + git status --short

读完先回我三行：当前阶段 / 未提交改动是什么 / 你建议的下一步。
在我点头之前不要改任何文件。
```

## 二、六条会话纪律

| # | 纪律 | 为什么 |
| --- | --- | --- |
| 1 | **一个会话只做一个模块**，做完就写 progress.md、提交、归档 | 赛题要求「每次提交对应一次 AI 核心对话」，会话粒度就是提交粒度 |
| 2 | 重活派给子智能体，主会话**只收 5 行结论** | 子智能体的上下文是独立的；但它的**全文回报会回到你这里**，P16 就是被四份长回报淹掉的 |
| 3 | 上下文到 60–70% 就压缩，不要等 100% | 到 100% 时连「压缩」这个动作本身都发不出去 |
| 4 | 只装这次用得上的插件 / MCP / 技能 | 它们的 schema 进系统提示词，是**每轮都在付**的固定成本（最后一次实测占 54%） |
| 5 | 图片、整份 PDF、docs/prompt-chain（16MB）不要贴进主会话 | 贴一次就永久留在上下文里；用路径 + 行号让子智能体自己去读 |
| 6 | 每个会话结束必须在 progress.md 追加一条 | 这是唯一能跨会话传递的东西，也是提交物 #2 的原料 |

## 三、判断自己快满了的三个信号

- 侧栏「当前上下文」超过 60%
- 某一轮开始变慢、模型开始忘掉前面的约定
- 报 `HTTP_413` / `发送内容过大`

出现任一条：立刻停手 → 写 progress.md → 开新会话。

## 四、旧会话里的东西还能要回来吗

能，但**不要靠重放对话**，直接读盘：

```
%APPDATA%\dsh-desktop\harness\sessions\--D-CZB--\<session-id>\session.v4.jsonl.zstd
```

每行一条记录、逐条 zstd 压缩（Node 24 自带 `zlib.zstdDecompressSync`），
按帧切开解压即可当纯文本用 `grep` / `tail` 翻。翻出来的结论写进 progress.md，比让模型重读一遍便宜三个数量级。
