# 还可以加什么：候选功能清单

> 这是第 11 条要求的产物：把「还能加什么」摊开来让人挑，而不是我替你决定。
> 每一项都标了「解决谁的什么问题」和「大概要花多久」，按**性价比**排序，不是按好写排序。
> 已上线的功能见 [README](../README.md) 功能表；这里只列**还没做**的。

## A. 先把「问」这件事做深（推荐优先）

现在一场沙盘是：抽主张 → 追问 → 判定 → 改写。链条是完整的，但「问」这一环有几个明显的缺口。

### A1. 让求职者能补一句真话（推荐 ★★★★★）

**问题**：候选人 Agent 被限定只能引用简历作答，所以「无法回答」这一类判定结构性偏少——它总能从简历里翻出一句勉强相关的话。
真实面试里人被问住时是可以补的：「这块简历上没写，但我实际做过，情况是……」而现在系统没有这个入口。

**怎么加**：追问到某条主张时，界面给一个输入框「补充一句真实情况」；补完的内容作为**新的证据片段**重新判一次，
并在报告里明确区分「简历里有的证据」和「你后来补充的证据」。

**成本**：约 4–6 小时（要动编排、要落库、要在报告里分栏）。**风险**：低，纯增量。

### A2. 追问难度档位：常规 / 压力（推荐 ★★★★）

**问题**：现在五位面试官的性格是固定的，压力面试官永远在施压，技术面试官永远温和。一场下来强度只有一个刻度。

**怎么加**：在投料台加一个「这场要多硬」的滑杆（温和 / 常规 / 挑刺），映射到追问预算的 `maxRoundsPerClaim`（2/3/4）
和提示词里的语气约束。**预算还是账本，不是提示词建议**——只是账本的参数由用户调。

**成本**：约 2–3 小时（预算本来就参数化，主要是界面与提示词）。

### A3. 报告加「按主张类别看短板」（推荐 ★★★★）

**问题**：现在 12 条主张平铺，用户看不出自己的系统性弱点是什么——是数字类主张普遍站不住，还是归属类普遍过度？

**怎么加**：`ClaimCategory` 七类已经有了，报告里按类别聚合判定分布，给一句结论（「你的数字类主张 5 条里 4 条站不住，
建议以后写效果时给出可复算的口径」）。技术文档 6.3 已把它列为待办 #3。

**成本**：约 2 小时（纯读库 + 渲染，不动编排）。

### A4. 反问环节（推荐 ★★★）

**问题**：真实面试最后有「你有什么想问我们的」。现在沙盘到判定就结束了。

**怎么加**：判定之后加一轮反问：用户提问，面试官按自己的契约（人设 + 立场）回答，答案也要锚定到简历或 JD。
**成本**：约 5 小时（新增一个阶段 + 一套提示词 + 一个界面区）。**价值**：演示效果好，评委会觉得「像个真面试」。

## B. 把「改」这件事收得更紧

### B1. 改写风格档位：保守 / 常规 / 敢改（推荐 ★★★★）

**问题**：现在采纳改写的口径是固定的——只删浮夸、只加可核验的限定。有人就想更狠一点。

**怎么加**：改写阶段加一档参数。注意**不能**突破现有硬约束：不许编简历里没有的数字（`newNumbersIn` 会拦），
不许把「参与」写成「主导」。档位只调「措辞收敛程度」，不调「事实边界」。

**成本**：约 2 小时。

### B2. 逐条并排的改动对照（推荐 ★★★）

**问题**：现在改完的简历标绿，报告里有改动清单，但没有「左边原文右边改后、逐条上下对齐」的视图。

**怎么加**：报告里加一栏并排 diff（两个 `<div>` 按 `movedSpans` 坐标切成同构段落）。
**成本**：约 2–3 小时。

### B3. 导出真 .docx 而不是 .doc（推荐 ★★）

**问题**：现在 Word 是 HTML 加 `.doc` 后缀，Word 打开会提示「格式与扩展名不一致」（能打开，但会弹一次警告）。

**怎么加**：自己拼 OOXML（`word/document.xml` 加最小 zip），不引第三方库——但这条路工作量大且容易在别人机器上崩。
**成本**：约 6–8 小时。**判断**：性价比低。提示那一下警告，比一个可能打不开的 docx 更安全。

## C. 让「反复用」更省事（这是从「工具」变成「产品」的分界）

### C1. 简历版本对比：同一份简历改完再跑一遍（推荐 ★★★★★）

**问题**：这是整个产品最有说服力的闭环，现在**差点意思**：改完导出、再上传跑一遍，两场结果不会自动关联。
用户看不到「上次被追问的那三条，这次站住了」。

**怎么加**：给会话加「上一版 / 这一版」的父子关系（同一份简历的 sha256 链），报告顶部加一块「比上次」：
判定分布变化、哪些主张从站不住变成站得住、追问次数变化。

**成本**：约 5–6 小时（要落库、要对齐两场的 claim 身份——`claim.id` 每场从 C1 重编，得按原文区间或文本相似度对齐）。
**这是我最想加的一项**：它把「一次体检」变成「连续跟踪」，也让演示视频有了第二条主线。

### C2. 历史仪表盘（推荐 ★★★）

**问题**：历史栏现在是场次列表，看不到趋势。

**怎么加**：历史里加一个小统计块：累计跑了几场、平均判定分布、最常被打回的主张类别。
**成本**：约 3 小时。

### C3. 一场导出成可分享的单文件 HTML（推荐 ★★★）

**问题**：现在能导出报告（md/html/pdf/doc）和简历（txt/html/doc），但没有「把整场打包成一个能发人的文件」。

**怎么加**：`GET /api/sessions/:id/bundle.html`，把报告 + 时间线 + 判定 + 建议串成一个自带样式的 HTML（图片走 data URI）。
**成本**：约 2–3 小时。

## D. 面向非计算机专业（第 4 条要求的延伸）

### D1. 行业模板库：一键凑齐 JD 与面试官（推荐 ★★★★）

**问题**：自建面试官已经能应付任何行业，但用户（比如护士、会计）不知道该配哪几位、该写什么 JD。

**怎么加**：内置 8–10 个行业的「JD 示例 + 推荐面试官组合」，投料台加一排「我是这个行业的」按钮，
点一下把两边都填好。数据就是现在 `DRAFT_SEEDS` 的放大版。

**成本**：约 3–4 小时（主要是写内容，代码很少）。**价值**：这是「非计算机专业也能用」的最后一公里。

### D2. 英文简历与英文追问（推荐 ★★）

**问题**：锚定逻辑本来与语言无关，但 `segment.ts` 的小节识别是中文关键词（「工作经历」「项目经验」）。
**怎么加**：加一套英文小节关键词 + 英文提示词。**成本**：约 4 小时。**判断**：赛题是中文语境，优先级低。

## E. 工程与复现（评分第 1 项 25% 权重吃这块）

### E1. 把卡带漂移门禁搬进 CI（推荐 ★★★★）

**问题**：现在「改提示词就会让卡带指纹失效」这条规则靠本地 `npm run verify` 守。仓库公开后，
如果有人在网页上直接改文件，这条规则就没人守了。

**怎么加**：一个 GitHub Actions 工作流：`npm ci` → `npm run verify` → `npm run repro`。公开仓库免费。
**成本**：约 1–2 小时（含第一次跑通）。**性价比很高**：评委点进仓库就能看到绿色徽章，
而「过程可复现性」正是 25% 权重。

### E2. 性能预算断言（推荐 ★★★）

**问题**：现在有实测数字（回放整场 21 ms、首屏可交互时间），但没有断言守着它们。
**怎么加**：在 e2e 里加两条断言：首屏可交互 < 1.5 s、回放整场 < 3 s；超了就红。
**成本**：约 2 小时。

### E3. 无障碍与纯键盘操作（推荐 ★★）

**问题**：弹层有 `role=dialog`，但焦点没有陷阱、Esc 关不掉；全流程能点，键盘走不完。
**怎么加**：焦点循环 + Esc 关闭 + `aria-live` 播报直播进度。**成本**：约 3 小时。

## 我的建议

如果只剩有限时间，按这个顺序做：**C1（简历版本对比）→ E1（CI 门禁）→ A1（补充事实）→ D1（行业模板）→ A3（按类别看短板）**。

理由：C1 是产品叙事的闭环，E1 直接吃 25% 权重的「过程可复现」，A1 补上判定区分度这个结构性缺口，
D1 兑现「所有专业都能用」，A3 成本最低但报告立刻好看。

其余的（B3 真 docx、D2 英文、E3 无障碍）我判断性价比低，除非你特别想要。
